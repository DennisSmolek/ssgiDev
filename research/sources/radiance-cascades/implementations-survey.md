# Implementations survey — GitHub / Shadertoy / engine ports

Short entries for every implementation found beyond the two deep-dived in `three-rc-implementation.md` (screen-space 3D, three.js) and `tlegoc-vulkan-implementation.md` (2D flatland, Vulkan). Grouped by dimensionality/approach per the task's ask.

## 2D flatland

- **fad's original Shadertoy** — https://www.shadertoy.com/view/mtlBzX — the implementation nearly every subsequent 2D port (Yaazarai's GameMaker version, GM Shaders tutorial, jason.today) cites as its direct ancestor. Treat as the "patient zero" of community 2D implementations.
- **Yaazarai/RadianceCascades** — https://github.com/Yaazarai/RadianceCascades — 2D GameMaker implementation directly based on fad's Shadertoy. Archived/read-only as of 2024-06-03. Controls: up/down = navigate cascade mip levels, left/right = adjust cascade-0 interval distance. Language mix: GameMaker Language 31.7%, GLSL 20.3%, Yacc 48% (build tooling).
- **Yaazarai/GMShaders-Radiance-Cascades** — https://github.com/Yaazarai/GMShaders-Radiance-Cascades — companion repo to the GM Shaders Part 1/2 posts; contains both the naive and the `RadianceCascades-Optimized/` (pre-averaged, direction-first) versions plus a `CascadeVisualDemo/`. See `gmshaders-radiance-cascades-part1.md` / `part2.md` for the technical content; repo tree confirmed via `gh api`.
- **otaviopeixoto1's portfolio writeup** — https://otaviopeixoto1.github.io/portfolio/2DRadianceCascades/ — custom OpenGL engine (OPEngine), mouse-drawn SDF as the light source, 5-cascade hierarchy, clean restatement of the canonical merge/interpolate pipeline. Good as a second independent confirmation of the standard recipe, no major novel content.
- **futureengine2 Gist** — https://gist.github.com/futureengine2/7c8fbc6fefce1818ff1edcd4d7e7bfcf — 2D GI implementation using WebGPU-API-like primitives; noted in search results but not deep-dived (low incremental value over the above).
- **compute.toys port** — https://compute.toys/view/1397 — another 2D shader-toy-style port; not deep-dived.
- **Sohojoe/radiance-cascades-godot** — https://github.com/Sohojoe/radiance-cascades-godot — Godot 4.3 port, explicitly a mashup of Yaazarai's GameMaker version and jason.today's JS implementation. Useful mainly as evidence of how portable the core algorithm is across engines once understood.
- **Youssef-Afella/UnityURP-RadianceCascades2DGI** — https://github.com/Youssef-Afella/UnityURP-RadianceCascades2DGI — Unity URP renderer-feature integration (C# 56.3% / ShaderLab 43.7%, MIT). Cites Sannikov, GM Shaders, Yaazarai, and NullTale's "GiLight" asset as references. Tested on RTX 3060. Notable as the most "production framework integration"-shaped 2D port (renderer feature + volume component pattern rather than a standalone demo).
- **Izendi/Radiance_Cascades_V1** — https://github.com/Izendi/Radiance_Cascades_V1 — OpenGL implementation credited directly as "My OpenGL implementation of Alexander Sannikov's Radiance Cascades global illumination solution." Not deep-dived; listed for completeness.
- **SimonDev / simondevyoutube/Shaders_RadianceCascades** — https://github.com/simondevyoutube/Shaders_RadianceCascades — GLSL, companion to SimonDev's three.js video (see `talks-and-videos.md`). Notable because other implementers (tlegoc) cite specific commits of this repo directly in their own shader code for the angle-interpolation math — treat this as a load-bearing reference implementation even though this pass didn't get full page content from its GitHub Pages front-end.

## 3D / world-space or screen-space

- **CodyJasonBennett/three-rc** — deep-dived separately, see `three-rc-implementation.md`. Screen-space probes + selectable BVH-world-space-interval or screen-space-raymarch tracing. **Best match for this project's stack.**
- **tmpvar/radiance-cascades-3d-grid** — https://github.com/tmpvar/radiance-cascades-3d-grid — "a rough implementation of Radiance Cascades using world space dense grids," C/GLSL/C++. **Currently non-functional**: depends on an unreleased hot-reload wrapper ("HotCart"). Has `DEVLOG.md`/`NOTES.md` dev notes (not fully retrieved). Classification: **pure world-space 3D grid**, the expensive/naive approach the paper explicitly warns is "practically equivalent to voxelizing the entire scene." Valuable as a documented cautionary data point, not as usable code.
- **tlegoc/RadianceCascadesGIVulkan** — deep-dived separately, see `tlegoc-vulkan-implementation.md`. 2D flatland only, despite being listed here for cross-reference (its author's stated future goal is 3D screen-space).
- **Yaazarai/Volumetric-HRC** — https://github.com/Yaazarai/Volumetric-HRC — "Constant-Time per-pixel volumetrics using ray-extensions and Holographic Radiance Cascades." Bridges to the academic follow-up work — see `academic-followups.md` for the related "Holographic Radiance Cascades" arXiv paper (same authorship cluster: Sannikov is a co-author on that paper).
- **noamzeise — "3D Radiance Cascades" dissertation** — code/writeup at https://noamzeise.com/drafts/2025-05-10-dissertation.html — see `academic-followups.md`; built in Common Lisp + OpenGL, explored grid-based then projection-space then view-space probes, compared against SSAO.

## Notes on classification confidence
"2D flatland" vs "3D screen-space" vs "3D world-space" labels above are based on repo README/blog descriptions plus (for the two deep-dived repos) direct source inspection. Where only a README summary was available (most entries here), treat the classification as reported-not-verified.
